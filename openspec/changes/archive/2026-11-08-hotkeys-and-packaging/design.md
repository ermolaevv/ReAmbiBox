# Technical Design: Глобальные горячие клавиши и упаковка дистрибутива

## Context

См. `proposal.md` — Мотивация и цели изменения.
Приложение `reambibox-app` является Win32-приложением на Rust (с подсистемой `windows`), работающим в фоновом режиме с веб-сервером на `http://localhost:3637` и иконкой в системном трее Windows.

## Goals / Non-Goals

**Goals:**
- Регистрация и перехват глобальных сочетаний клавиш в Windows (`Ctrl+Shift+A`, `Ctrl+Shift+Up`, `Ctrl+Shift+Down`, `Ctrl+Shift+O`).
- Мгновенная реакция подсветки на хоткеи без необходимости открытия веб-интерфейса.
- Поддержка аргумента командной строки `--minimized` для запуска без консоли и окон.
- Автоматическая регистрация автозапуска с ключом `--minimized`.
- Готовые скрипты для сборки портативного ZIP-релиза и установщика Windows (Inno Setup).

**Non-Goals:**
- Низкоуровневые клавиатурные хуки (`SetWindowsHookExW`): не требуются, стандартного API `RegisterHotKey` достаточно для регистрации глобальных хоткеев и он безопаснее для античитов в играх.
- Разработка собственного кастомного GUI-инсталлятора на Rust: вместо этого используется признанный отраслевой стандарт Windows-установщиков — Inno Setup.

## Decisions

### 1. Интеграция `RegisterHotKey` в цикл сообщений трея
- **Решение**: Использовать существующее скрытое окно и цикл сообщений Win32 в `crates/reambibox-app/src/tray.rs` для регистрации хоткеев.
- **Обоснование**: `tray.rs` уже управляет скрытым окном с циклом `GetMessageW` / `DispatchMessageW` в выделенном потоке ОС. Добавление `RegisterHotKey` и обработка сообщения `WM_HOTKEY` позволяет избежать создания лишних потоков и накладных расходов.
- **Идентификаторы хоткеев**:
  - `HOTKEY_TOGGLE_POWER = 101` (`MOD_CONTROL | MOD_SHIFT`, `'A'`)
  - `HOTKEY_BRIGHTNESS_UP = 102` (`MOD_CONTROL | MOD_SHIFT`, `VK_UP`)
  - `HOTKEY_BRIGHTNESS_DOWN = 103` (`MOD_CONTROL | MOD_SHIFT`, `VK_DOWN`)
  - `HOTKEY_TOGGLE_OVERLAY = 104` (`MOD_CONTROL | MOD_SHIFT`, `'O'`)
- **Альтернативы**:
  - Отдельный поток с окном для хоткеев: избыточное дублирование очередей сообщений Windows.
  - Raw Input / Low-Level Hook: создаёт риск блокировок ввода и ложных срабатываний античитов.

### 2. Тихий запуск и замещение старого процесса (Single Instance Takeover)
- **Решение**: Реализовать процедуру `ensure_single_instance_takeover()` на самом раннем этапе `main()` до открытия COM-порта и сокетов TCP.
- **Логика работы**:
  - Получение собственного PID через `std::process::id()`.
  - Сканирование процессов Windows через Toolhelp32 API (`CreateToolhelp32Snapshot(TH32CS_SNAPPROCESS, 0)`).
  - Поиск всех процессов с именем `reambibox-app.exe`, чей PID отличен от текущего.
  - Завершение найденного процесса через `OpenProcess(PROCESS_TERMINATE | SYNCHRONIZE, false, pid)` и `TerminateProcess`.
  - Ожидание полного завершения через `WaitForSingleObject(h_proc, 2000)` и кратковременная пауза (200 мс) для освобождения ресурсов Windows (COM-порта и сетевых портов 3637/3636).
- **Аргумент `--minimized`**:
  - Если передан `--minimized` или `--silent`: подавлять подключение к родительской консоли (`init_console_support` пропускается) и не открывать браузер.
  - Если запускается вручную пользователем без аргументов: поведение остаётся прежним (при наличии консоли выводятся логи).
  - В `autostart.rs` значение реестра `Run` форматируется как `format!("\"{}\" --minimized", exe_path.display())`.

### 3. Структура дистрибуции
- **Каталог**: `scripts/` в корне репозитория.
- **`package.ps1`**:
  - Запуск `cargo build --release`.
  - Формирование каталога `target/dist/ReAmbiBox/` со структурой:
    - `reambibox-app.exe`
    - `README.txt`
  - Создание архива `ReAmbiBox-Portable.zip`.
- **`installer.iss`**:
  - Inno Setup скрипт с поддержкой русскоязычного интерфейса, указанием иконки приложения, установкой в `{autopf}\ReAmbiBox`, добавлением ярлыка в меню «Пуск» и созданием деинсталлятора.

## Risks / Trade-offs

- **[Конфликт хоткеев с другими приложениями]** → `RegisterHotKey` возвращает ошибку, если комбинация занята другой программой. Система логирует предупреждение и продолжает работу, не прерывая запуск.
- **[Отсутствие Inno Setup на машине сборки]** → Скрипт `package.ps1` проверяет наличие компилятора `ISCC.exe`. Если Inno Setup установлен — собирает `.exe` установщик; если нет — собирает полноценный портативный `.zip` архив и выводит подсказку.
