# Design: presets-management

## Context
В настоящее время `AppConfig` хранит плоский список параметров. Настоящий дизайн вводит концепцию пользовательских пресетов (`Preset`), разделяя настройки на глобальные аппаратные (COM-порт, геометрия зон, автозапуск) и профильные параметры отображения. Предустановленные заводские пресеты отсутствуют — список пресетов полностью создается и контролируется пользователем.

## Goals / Non-Goals

**Goals:**
- Введение легковесной структуры `Preset` со снимком параметров рендеринга.
- Чистый список пресетов по умолчанию (без захардкоженных фабричных профилей).
- Возможность сохранять текущие настройки как пресет, перезаписывать и удалять любой созданный пресет.
- Быстрое переключение через селектор в WebUI и контекстное меню трея Windows.
- Атомарное применение пресета с обновлением `config_version` без задержек и перезапуска.

**Non-Goals:**
- Встроенные нередактируемые заводские пресеты (исключены по требованию пользователя).
- Дублирование геометрии зон внутри пресетов (зоны откалиброваны физически под экран и остаются общими).

## Decisions

### 1. Модель данных `Preset` в `reambibox-core`
```rust
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct Preset {
    pub id: String,
    pub name: String,
    pub mode: String,
    pub brightness: f32,
    pub smoothing: f32,
    pub gamma: f32,
    pub saturation_boost: f32,
    pub white_balance_r: f32,
    pub white_balance_g: f32,
    pub white_balance_b: f32,
    pub black_level_threshold: u8,
    pub letterbox_detection: bool,
    pub target_fps: u32,
    pub static_color: [u8; 3],
    pub audio_effect: String,
    pub audio_sensitivity: f32,
}
```

### 2. Список пресетов по умолчанию
- `presets: Vec<Preset>` инициализируется как пустой вектор `Vec::new()`.
- При сохранении генерируется уникальный `id` (например, на основе timestamp или слагофицированного имени).

### 3. REST API маршруты
- `POST /api/presets/apply` с телом `{"id": "preset_id"}` — находит пресет, применяет его значения к `AppConfig`, инкрементирует `config_version`, выставляет `active_preset = Some(id)` и сохраняет конфиг.
- `POST /api/presets/save` с телом `{"name": "Мой пресет", "id": "optional_id"}` — сохраняет текущие параметры подсветки в список. Если `id` передан и найден, перезаписывает существующий пресет; если нет — добавляет новый.
- `POST /api/presets/delete` с телом `{"id": "preset_id"}` — удаляет пресет из списка.

### 4. Интеграция с UI
- В шапке WebUI появляется выпадающий список или компактная панель пресетов с кнопками «Сохранить текущие» и «Удалить».
- В трее Windows создается динамическое подменю `Пресеты` -> со списком созданных пользователем пресетов и галочкой `MF_CHECKED` на активном (если ни один не выбран, подменю пустое или содержит пункт «Нет сохраненных пресетов»).

## Risks / Trade-offs

- **[Risk]** Пользователь применил пресет, а затем изменил один ползунок вручную.
  → *Mitigation*: При ручном изменении любого параметра `active_preset` сбрасывается в `None` (или помечается звездочкой `*`), чтобы пользователь видел, что настройки были модифицированы относительно сохраненного профиля.
