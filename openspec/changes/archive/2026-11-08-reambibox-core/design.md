# Design: Архитектура и технический дизайн ReAmbiBox

## Context

См. `proposal.md` для мотивации и целей. Текущий репозиторий представляет собой чистую кодовую базу. Для полной замены устаревшего AmbiBox проектируется многопоточный конвейер реального времени с ультранизкими задержками и минимальным потреблением ресурсов Windows.

## Goals / Non-Goals

**Goals:**
- Обеспечить непрерывный захват экрана 60–120 кадров/сек с нулевой нагрузкой на CPU через DirectX 11 / DXGI Desktop Duplication.
- Вычислять цвета зон и передавать пакеты Adalight в порт COM10 с задержкой от кадра до светодиода менее 15 мс.
- Поддерживать стандартный текстовый протокол Lightpack API (порт 3636) для совместимости со сторонними интеграциями.
- Предоставить интерактивный полупрозрачный редактор зон с масштабированием под мультимониторные конфигурации и HiDPI.
- Спроектировать модульный интерфейс драйверов для легкого добавления AtmoLight, Paintpack, SEDU и WLED в будущем.

**Non-Goals:**
- Реализация встроенного ИК-сервера (IR Receiver), эмуляции кнопок мыши и мультимедиа-клавиатуры.
- Воспроизведение устаревших методов захвата (GDI Screen DC, DirectDraw) — поддерживается только современный стек DXGI.
- Поддержка операционных систем, отличных от Windows 10 и Windows 11 (на данном этапе).

## Decisions

### 1. Язык и платформа: Rust + Tauri 2.0
* **Решение**: Использовать **Rust** для высокопроизводительного нативного ядра (захват, вычисления, COM-порт, сетевой сервер) и **Tauri 2.0** (HTML5/TypeScript/CSS поверх встроенного в Windows WebView2) для пользовательского интерфейса.
* **Почему не чистый C++**: Разработка сложного GUI (особенно прозрачного полноэкранного оверлея с масштабированием под разный DPI) на WinUI 3/C++ или Qt требует значительно больше времени и увеличивает размер приложения. На связке Rust + Tauri интерфейс пишется легко и весит всего ~10–15 МБ, потребляя в фоне ~30–45 МБ RAM.
* **Почему не C# / .NET 9**: .NET требует распаковки тяжелого рантайма (70–100+ МБ), а управление прозрачными окнами оверлея в WinUI 3 имеет ряд известных платформенных ограничений.

### 2. Модель многопоточности и конвейер данных
* **Архитектура конвейера**:
```
+------------------------------------------------------------------------------------+
|                                PIPELINE АРХИТЕКТУРА                                |
+------------------------------------------------------------------------------------+
|                                                                                    |
| [Поток захвата (DXGI Capture Thread)]                                              |
|   - Ожидание следующего кадра (AcquireNextFrame, timeout 50ms)                     |
|   - Копирование текстуры в staging-буфер GPU                                       |
|   - Извлечение пикселей в память кадра                                            |
|                            |                                                       |
|                            v (Crossbeam / Lock-free channel: LatestFrame)          |
|                                                                                    |
| [Поток обработки цвета (Color Processing Thread)]                                  |
|   - Расчет среднего цвета по полигонам/прямоугольникам зон (SIMD-downsampling)     |
|   - Детекция черных полос (letterbox) и смещение зон                               |
|   - Временное сглаживание: Color[t] = Color[t-1] * a + Target * (1 - a)            |
|                            |                                                       |
|                            v (Crossbeam channel: RgbPayload)                        |
|                                                                                    |
| [Поток вывода устройства (Device Output Worker)]                                    |
|   - Формирование пакета Adalight ("Ada" + Hi + Lo + CRC + RGB)                     |
|   - Запись в COM-порт (COM10, 115200 бод, overlapped IO)                           |
|                                                                                    |
+------------------------------------------------------------------------------------+
|                                                                                    |
| [Асинхронный сервер совместимости (Tokio Runtime)]                                 |
|   - Прослушивание TCP 127.0.0.1:3636 (Lightpack API)                               |
|   - Управление глобальным состоянием и профилями через `Arc<RwLock<AppState>>`     |
|                                                                                    |
| [Интерфейс пользователя (Tauri IPC / WebView2)]                                    |
|   - Главное окно настроек (COM-порты, профили, калибровка)                         |
|   - Полноэкранное прозрачное окно калибровки зон (Click-through / Interactive)     |
|                                                                                    |
+------------------------------------------------------------------------------------+
```
* **Обоснование**: Разделение на независимые потоки предотвращает просадку частоты захвата из-за медленного COM-порта (115200 бод передает 300 байт за ~2.6 мс). Если COM-порт запаздывает, промежуточные устаревшие кадры сбрасываются без накопления задержки (lag-free drop policy).

### 3. Структура конфигурации
* Хранение конфигурации профилей и геометрии зон в формате JSON (`%APPDATA%\ReAmbiBox\config.json`), что обеспечивает легкое резервное копирование и редактирование, в отличие от устаревшего реестра Windows.

## Risks / Trade-offs

- **[Риск]: Блокировка захвата DXGI защищенным контентом (DRM/HDCP в Netflix, браузере)**
  $\rightarrow$ *Решение*: Обнаружение ошибки DXGI_ERROR_ACCESS_LOST / DXGI_ERROR_UNSUPPORTED, автоматический fallback на фоновый мягкий цвет или повторное подключение после сворачивания защищенного окна.
- **[Риск]: Ограничение пропускной способности COM-порта при большом числе диодов (более 200)**
  $\rightarrow$ *Решение*: Предоставление пользователю выбора скорости порта (до 256000 / 500000 бод при поддержке контроллером) и динамический ограничитель FPS отправки (`TargetDeviceFPS`), чтобы не перегружать буфер UART Arduino.
- **[Риск]: Падение сессии рабочего стола при UAC или Winlogon (Ctrl+Alt+Del)**
  $\rightarrow$ *Решение*: Изоляция пересоздания объекта Desktop Duplication в цикле восстановления без аварийного завершения процесса приложения.

## Migration Plan

1. Подтверждение доступности и корректной работы COM10 на тестовом синтетическом Adalight-пакете.
2. Проверка работы захвата экрана на одном основном мониторе через тестовый DXGI-раннер.
3. Развертывание полнофункционального приложения в пользовательскую директорию без необходимости инсталляторов.
