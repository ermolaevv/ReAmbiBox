# Design: Режим светомузыки (Audio Reactive / Music Visualizer)

## Context

В Windows стандартным высокопроизводительным способом перехвата воспроизводимого звука является Windows Audio Session API (WASAPI) в режиме `AUDCLNT_STREAMFLAGS_LOOPBACK`.
ReAmbiBox уже имеет конвейер вывода кадров (`DeviceFrame`) в Adalight на высокой частоте.
См. `proposal.md` для мотивации.

## Goals / Non-Goals

**Goals:**
- Реализовать фоновый поток захвата звука через WASAPI Loopback (без сторонних DLL и без виртуальных драйверов).
- Реализовать быстрое разделение спектра на 3 ключевые полосы: Бас (20-250 Гц), Средние (250-2500 Гц), Высокие (2500-16000 Гц) с автоподстройкой усиления (AGC).
- Поддержать 3 визуальных эффекта:
  1. `pulse` (пульсирующий цветной бит).
  2. `spectrum` (VU-метр / эквалайзер от нижних углов к верхним).
  3. `wave` (бегущая звуковая волна по кругу).
- Переключение в Web UI (кнопка режима «Светомузыка», выбор эффекта, ползунок чувствительности).

**Non-Goals:**
- Профессиональный DAW-аудиоредактор.
- Захват с физического микрофона (захватывается системный звук, который слышит пользователь).

## Decisions

### 1. WASAPI Loopback вместо `cpal`
- **Решение**: Использовать прямой Windows API через `windows::Win32::Media::Audio` с `CoInitializeEx`, `IMMDeviceEnumerator` и `IAudioClient`.
- **Обоснование**: Минимальный размер бинарника, нулевые внешние зависимости, идеальная совместимость с Windows 10/11 и Per-Monitor/Modern API.

### 2. Алгоритм спектрального анализа
- **Решение**: Скользящее окно 512–1024 сэмплов с расчетом среднеквадратичной энергии (RMS) и БПФ / полосовых фильтров (Goertzel/FFT) с экспоненциальным сглаживанием пиков и адаптивным шумоподавлением.
- **Обоснование**: Потребление CPU < 0.2% одного ядра при 60 FPS светомузыки.

## Risks / Trade-offs

- [Тишина или отсутствие воспроизведения звука] → При отсутствии аудиоданных система плавно гасит диоды или переходит в мягкое фоновое свечение вместо резкого отключения.
