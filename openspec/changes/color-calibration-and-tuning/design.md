# Design: color-calibration-and-tuning

## Context
В текущей реализации ReAmbiBox модуль `GammaLut` кэширует единый 256-байтный массив для всех каналов. Любая дополнительная поканальная математика (например, умножение на `gain_r, gain_g, gain_b`) или расчет порога черного непосредственно в цикле кадра привела бы к потере производительности. Настоящий дизайн объединяет баланс белого, яркость и порог чёрного в расширенную структуру `GammaLut`, сохраняя константную сложность $O(1)$ и нулевые накладные расходы на кадр.

## Goals / Non-Goals

**Goals:**
- Независимая калибровка каналов R, G, B для компенсации цвета стены и спектра ленты.
- Настраиваемый порог отсечки чёрного (Black Level Threshold) для устранения паразитного свечения в тёмных сценах.
- Быстрое масштабирование насыщенности (Saturation Boost) без цветовых сдвигов тона.
- Полная интеграция с WebUI с динамическими ползунками и сохранением в `config.json`.
- Сохранение высокой производительности конвейера ($O(1)$ выборка из L1-кэша без аллокаций).

**Non-Goals:**
- Сложные трехмерные 3D-LUT матрицы (слишком высокое потребление памяти и избыточность для светодиодной ленты).
- Индивидуальная поканальная калибровка для каждого отдельного светодиода (глобальной калибровки ленты достаточно).

## Decisions

### 1. Расширение `GammaLut` до 3 раздельных каналов (`lut_r`, `lut_g`, `lut_b`)
- **Решение**: Вместо вычисления `(pixel * gain)` в цикле каждого светодиода перенести коэффициенты усиления R/G/B в предрасчет LUT. Таблица занимает 768 байт ($3 \times 256$), что с запасом укладывается в 32 КБ L1 Data Cache современного процессора.
- **Альтернатива**: Вычислять умножение в рантайме. Отклонено: создает до 18 000 операций умножения с плавающей точкой в секунду на кадре.

### 2. Порог отсечки чёрного на уровне `GammaLut::correct_color`
- **Решение**: Если яркость всех трёх компонентов $R, G, B \le \text{black\_threshold}$, метод мгновенно возвращает `RgbColor::BLACK`. Это эффективно гасит ленту на темных кадрах и титрах без необходимости запуска сложных эвристик.
- **Диапазон**: 0–50 (0 — отключено, значения 5–15 идеальны для фильмов).

### 3. Регулировка насыщенности через веса Luma (Rec. 601)
- **Решение**: Использовать формулу:
  $$\text{Luma} = 0.299 \cdot R + 0.587 \cdot G + 0.114 \cdot B$$
  $$C' = \text{clamp}(\text{Luma} + (C - \text{Luma}) \cdot \text{saturation}, 0, 255)$$
  Если `saturation == 1.0`, шаг полностью пропускается без каких-либо вычислений (fast-path).
- **Альтернатива**: Полное преобразование в RGB -> HSL -> RGB. Отклонено из-за высокой вычислительной стоимости деления и тригонометрии.

### 4. Версионирование конфигурации
- Изменение слайдеров калибровки инкрементирует `config_version: Arc<AtomicU64>`, что заставляет поток захвата один раз пересчитать 768-байтную LUT-таблицу и продолжать рендеринг на полной скорости.

## Risks / Trade-offs

- **[Risk]** Слишком высокий порог отсечки чёрного может вызывать резкое включение/выключение подсветки на граничных сценах.
  → *Mitigation*: Временное экспоненциальное сглаживание (`TemporalSmoother`) сглаживает переход, исключая мерцание. В UI порог ограничен разумным диапазоном 0–50 с подсказкой рекомендуемых значений (0–15).
- **[Risk]** Завышенные коэффициенты усиления (> 1.5) могут приводить к клиппингу (насыщению канала до 255).
  → *Mitigation*: Значения строго ограничиваются `clamp(0.0, 1.0)` при формировании LUT, исключая числовое переполнение.
