# Design: Интеграция с рабочим столом Windows, системный трей и управление питанием

## Context

В настоящее время ReAmbiBox запускается как консольная утилита с открытым окном терминала. Для комфортной фоновой работы требуется интеграция с подсистемами Windows:
- Win32 Message Loop для обработки системных событий трея, питания и завершения сеанса;
- `Shell_NotifyIconW` для управления иконкой в системном трее;
- Реестр Windows (`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`) для автозагрузки;
- `RegisterPowerSettingNotification` и `WTSRegisterSessionNotification` для отслеживания состояния дисплея и блокировки ПК;
- Обработчики завершения процесса (`SetConsoleCtrlHandler`, `WM_ENDSESSION`, RAII Drop Guard) для гарантированного отключения диодов.

## Goals / Non-Goals

**Goals:**
- Работа в системном трее без открытого черного окна консоли в фоновом режиме.
- Контекстное меню трея (Вкл/Выкл подсветку, Панель управления, Автозапуск, Выход).
- Открытие веб-панели управления в браузере по клику на иконку трея.
- Автозапуск приложения при входе пользователя в Windows.
- Автоматическое гашение диодов при блокировке ПК (`Win + L`) и при выключении экрана монитора по таймауту Windows.
- Гарантированное выключение всех светодиодов (отправка чёрного кадра) при любом способе завершения приложения (Ctrl+C, меню «Выход», завершение работы Windows, паника).
- Возможность запуска с флагом `--console` для отладки.

**Non-Goals:**
- Встраивание тяжелого браузерного движка (WebView2 / Chromium) внутрь exe — интерфейс уже быстро и легковесно работает через браузер на `http://localhost:3637`.
- Поддержка операционных систем Linux/macOS в рамках этого изменения (фокус строго на Windows).

## Decisions

### 1. Реализация системного трея и цикла сообщений
- **Решение**: Использование нативных вызовов Windows API (`Shell_NotifyIconW`, `CreatePopupMenu`, `TrackPopupMenuEx`) или крейта `tray-icon` с запуском цикла обработки сообщений Win32 (`GetMessageW` / `DispatchMessageW`) в отдельном выделенном потоке интерфейса.
- **Обоснование**: Минимальный размер бинарника, нулевое потребление памяти (< 1 МБ), мгновенный отклик меню и отсутствие конфликтов с циклом Tokio.
- **Альтернативы**: Полноценный фреймворк GUI (Tauri / Slint) — отклонён из-за избыточности (добавляет 10-20 МБ зависимостей к легковесному драйверу подсветки).

### 2. Скрытие консольного окна и режим отладки
- **Решение**: Использование атрибута `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]` в `main.rs`. При передаче аргумента командной строки `--console` приложение явно вызывает `AttachConsole(ATTACH_PARENT_PROCESS)` или `AllocConsole()` для перенаправления логов в терминал.
- **Обоснование**: При обычном клике на exe окно консоли не появляется, но при разработке и отладке в терминале логи остаются доступны.

### 3. Автозапуск через Windows Registry
- **Решение**: Чтение и запись строкового значения `ReAmbiBox = "<PathToExe>"` в ветку `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run`.
- **Обоснование**: Не требует прав администратора (UAC), стандартный путь для пользовательских фоновых утилит Windows.

### 4. Отслеживание сна, блокировки экрана и выключения Windows
- **Решение**:
  - Регистрация на события питания монитора через `RegisterPowerSettingNotification` для `GUID_MONITOR_POWER_ON`.
  - Регистрация на события пользовательской сессии через `WTSRegisterSessionNotification(hwnd, NOTIFY_FOR_THIS_SESSION)`.
  - Обработка `WM_QUERYENDSESSION` / `WM_ENDSESSION` в оконной процедуре Win32.
  - При получении `PBT_POWERSETTINGCHANGE` (монитор выключен) или `WTS_SESSION_LOCK`: флаг `is_active` переводится в `false` с отправкой чёрного кадра. При `GUID_MONITOR_POWER_ON` (экран включен) или `WTS_SESSION_UNLOCK` восстанавливается прежнее состояние.

### 5. Гарантированное гашение диодов при любом завершении программы
- **Решение**: Трёхуровневая защита:
  1. **RAII Drop Guard в драйвере устройства**: в `AdalightDriver::disconnect()` и `impl Drop for AdalightDriver` отправляется синхронный чёрный кадр `DeviceFrame::new(vec![RgbColor::BLACK; count])` с `port.flush()`.
  2. **Сигналы ОС**: регистрация обработчиков `ctrlc::set_handler` и `SetConsoleCtrlHandler` (Ctrl+C, закрытие консоли), которые вызывают корректное завершение потоков с тушением подсветки.
  3. **std::panic::set_hook**: хук паники перед выводом ошибки пытается перехватить порт и отправить чёрный кадр, исключая «зависание» диодов во включенном состоянии при неожиданном сбое.

## Risks / Trade-offs

- **[Risk]** Цикл сообщений Windows блокирует или конфликтует с Tokio.
  - **Mitigation**: Win32 Message Loop выносится в отдельный изолированный поток ОС (`tray_worker`), общающийся с `shared_config` через атомики и каналы.
- **[Risk]** При принудительном `taskkill /F` процесс убивается ядром без вызова пользовательского кода.
  - **Mitigation**: Стандартный `taskkill` без `/F`, закрытие окна, Ctrl+C, выключение ПК и выход через трей обрабатываются полностью.
