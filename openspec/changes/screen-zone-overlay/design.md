# Technical Design: Нативный экранный оверлей зон захвата и мастер периметра

## Context
В `ReAmbiBox` захват экрана осуществляется через DXGI Desktop Duplication на базе нормализованных прямоугольников `NormalizedRect` (от 0.0 до 1.0). Конфигурация хранится в `AppConfig.zones` и разделяется через `Arc<RwLock<AppConfig>>`.
В оригинальном AmbiBox визуальная настройка зон выводила пронумерованные прямоугольники поверх всех окон, позволяя пользователю вручную подогнать их под диоды или запустить мастер.
См. `proposal.md` для мотивации.

## Goals / Non-Goals

**Goals:**
- Создание полноэкранного поверхностного прозрачного оверлея (`WS_EX_TOPMOST | WS_EX_LAYERED | WS_EX_TOOLWINDOW`) на выбранном мониторе.
- Отображение всех активных зон (1..N) с полупрозрачной заливкой, контрастной рамкой и крупным номером зоны.
- Интерактивный Drag & Drop: перетаскивание зоны мышью и изменение размера с мгновенной передачей новых координат в поток сэмплирования DXGI.
- Визуальный мастер расстановки зон по периметру (Top, Bottom, Left, Right, Start Corner, Direction, Depth, Margin) в Web UI.
- Возможность вызова оверлея через Web UI («Показать зоны на экране»), из трея и по нажатию клавиши `F7` / `Esc` (для закрытия).

**Non-Goals:**
- 3D проекции зон или искривление формы (прямоугольные зоны покрывают 100% потребностей Ambilight).

## Decisions

1. **Единое прозрачное окно оверлея вместо 98 отдельных HWND**:
   - *Решение*: Использовать одно полноэкранное окно с `WS_EX_LAYERED` и цветовым ключом / альфа-каналом, на котором рисуются все зоны, вместо создания 98 отдельных независимых окон Win32.
   - *Обоснование*: Создание 98 отдельных окон в Win32 вызывает мерцание z-order, артефакты фокуса и избыточную нагрузку на оконный менеджер Windows (DWM). Единый оверлей обеспечивает мгновенный 60 FPS рендеринг, легкий хит-тестинг мыши, поддержку подсветки активной перетаскиваемой зоны и возможность отрисовки вспомогательных линий сетки.
   - *Альтернативы*: 98 независимых окон (как в Delphi/AmbiBox 2013 года) — отклонено из-за нестабильности в современных сборках Windows 11.

2. **GDI+ / Direct2D полупрозрачный рендеринг зон**:
   - Каждая зона рисуется с полупрозрачным фоном (альфа ~35%), яркой рамкой (2px) и центрированным контрастным номером (белый текст с тёмной обводкой для читаемости на любом фоне).
   - Выбранная (перетаскиваемая) зона подсвечивается неоновым цветом и отображает маркеры изменения размера (Resize Handles).

3. **Синхронизация с потоком захвата (Zero-Latency Live Preview)**:
   - При перемещении зоны мышью её нормализованные координаты `(x, y, w, h)` сразу записываются в `shared_config`.
   - Поток DXGI захвата считывает цвета из разделяемой конфигурации каждый кадр, поэтому диоды на стене мгновенно реагируют на перемещение зоны мышкой!

4. **Мастер расстановки зон (`ZoneWizard`)**:
   - Расширение алгоритма `ZoneWizard::generate_custom_perimeter(...)` с параметрами:
     - `top_count`, `bottom_count`, `left_count`, `right_count`
     - `start_corner`: `BottomLeft`, `BottomRight`, `TopLeft`, `TopRight`
     - `direction`: `Clockwise`, `CounterClockwise`
     - `depth`: глубина зоны в процентах (по умолчанию 8%)
     - `margin`: отступ от края экрана
   - Вызов мастера доступен через Web UI (`POST /api/zones/wizard`) с мгновенным обновлением на экране.

## Risks / Trade-offs

- **[Риск] Перехват кликов мыши на оверлее**: Когда оверлей открыт, клики по экрану попадают в зоны оверлея, а не в лежащие под ними окна.
  - *Митигация*: Отображение плавающей плашки «Режим калибровки зон: нажмите Esc для сохранения и закрытия», закрытие по клавише `Esc`, кнопке в Web UI или повторному клику в трее. В обычном режиме оверлей закрыт и клики мыши никак не перехватывает.
- **[Риск] Многомониторные конфигурации**: Пользователь может запускать калибровку на вторичном мониторе.
  - *Митигация*: Оверлей создается строго на координатах прямоугольника `MONITORINFO` выбранного в настройках монитора.
